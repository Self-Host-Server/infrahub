# IPAM Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A compose service that keeps Infrahub's IPAM filled from Proxmox and an nmap scan of `192.168.1.0/24`, every 15 minutes, removing stale entries it created.

**Architecture:** Python package `ipam_sync/` run in an image built `FROM` the Infrahub image plus `nmap`, with host networking. Pure parsing and decision functions (no network, unit-tested) are separate from the two I/O modules: `proxmox.py` fetches over HTTP, `store.py` writes through `infrahub_sdk`. `main.py` runs the loop.

**Tech Stack:** Python 3.14 (the image's), `httpx` 0.28 and `infrahub-sdk` 1.11.10 (both already in the image), `nmap` (Debian trixie package), pytest, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-11-11-ipam-sync-design.md`

## Global Constraints

- Every object the sync creates has `managed_by = "ipam-sync"`. Nothing without it is ever updated or deleted.
- Never delete Proxmox-derived objects unless the guest-list API call succeeded.
- Only IPv4 addresses inside `IPAM_SCAN_SUBNETS` are recorded, stored with the subnet's prefix length (`192.168.1.20/24`).
- MAC addresses are stored lowercase, colon-separated.
- Defaults: `IPAM_SCAN_SUBNETS=192.168.1.0/24`, `IPAM_SYNC_INTERVAL_MINUTES=15`, `IPAM_STALE_DAYS=7`, `PROXMOX_VERIFY_TLS=false`.
- Proxmox is optional: with `PROXMOX_URL` empty the service runs scan + cleanup only. Never use `${VAR:?}` for its variables (it would break `docker compose up` for existing installs).
- Proxmox auth header: `Authorization: PVEAPIToken=<PROXMOX_TOKEN_ID>=<PROXMOX_TOKEN_SECRET>`.
- Plain functions, no classes (repo style). Ruff line length 180. New secrets go in `.env.example` as `replace_me`.
- Commits authored by the repo's git user only; no AI co-author trailers.

## Review Focus

1. One guest's config call fails (HTTP 500) while the list call succeeded → that guest is still returned (no NICs) and is **not** deleted. Test in Task 3.
2. VM guest agent not running (Proxmox returns 500 for `agent/network-get-interfaces`) → guest returned with MACs from config, no IPs, no exception. Test in Task 3.
3. A hand-made IP exists at an address the scan sees → left untouched. Test in Task 2 (`plan_ip_write`).
4. MAC case differs between Proxmox config (upper), agent (lower) and nmap (upper) → still matched. Test in Task 2 (`normalize_mac`) and Task 4.
5. Two guests share a name → second becomes `<name>-<vmid>`, both kept. Test in Task 2 (`unique_guest_names`).

### Task 3: Proxmox client

**Files:**

- Create: `ipam_sync/proxmox.py`
- Test: `tests/ipam_sync/test_proxmox.py`

**Interfaces:**

- Consumes: `normalize_mac`, `unique_guest_names` from Task 2.
- Produces:
  - `parse_net(value: str) -> dict` → `{"mac": str | None, "ip": str | None}`. Handles VM form `virtio=BC:24:..,bridge=vmbr0` (MAC = the first `key=value` value matching `^[0-9A-Fa-f]{2}(:[0-9A-Fa-f]{2}){5}$`) and LXC form `name=eth0,hwaddr=BC:..,ip=192.168.1.20/24` (`ip=dhcp`/`manual` → `None`).
  - `parse_agent(payload: dict) -> dict[str, list[str]]` → MAC → list of IPv4 strings, from `payload["data"]["result"][*]["hardware-address"]` and `["ip-addresses"][*]` where `ip-address-type == "ipv4"`.
  - `fetch_guests(client: httpx.Client) -> list[dict]` → each `{"name", "vmid", "node", "type", "nics": [{"name": "net0", "mac": str | None, "ips": [str]}]}`, passed through `unique_guest_names`. Raises `httpx.HTTPError` if `GET /api2/json/cluster/resources?type=vm` fails. Per-guest config or agent failures are swallowed (guest kept, missing data empty). Skips templates (`template == 1`).
  - `make_client(url: str, token_id: str, token_secret: str, verify: bool) -> httpx.Client` (base URL, auth header, 10 s timeout).

### Task 5: Infrahub writes, loop, and compose service

**Files:**

- Create: `ipam_sync/store.py`, `ipam_sync/main.py`, `ipam_sync/Dockerfile`
- Modify: `compose.yml` (new `ipam-sync` service), `.env.example` (Proxmox + IPAM vars), `README.md` (Proxmox token steps, manual run command), `.dockerignore` only if the build context needs it

**Interfaces:**

- Consumes: everything from Tasks 2–4.
- Produces (`store.py`, takes an `InfrahubClientSync`):
  - `sync_guests(client, guests: list[dict], subnets: list[str], now: datetime) -> None`: ensure managed `IpamPrefix` per subnet if none exists; upsert `ProxmoxNode` per node, `VirtualizationVirtualMachine` per guest (`host` = node), `InterfaceVirtual` per NIC (`mac_address`, `status="active"`, `device` = VM), managed `IpamIPAddress` per `to_cidr` IP with `last_seen=now`, `mac_address`, `interface`; then delete managed VMs (with their managed interfaces) and nodes not in this run via `select_deletions`.
  - `record_scan(client, hits: list[dict], subnets: list[str], now: datetime) -> None`: for each hit with a `to_cidr` address, apply `plan_ip_write`; on create/update set `last_seen`, `mac_address`, and `interface` when a managed `InterfaceVirtual` has that MAC.
  - `delete_stale(client, now: datetime, days: int) -> int`: delete managed IPs where `is_stale`.
- Produces (`main.py`): `run_once(config: dict) -> None` (each of the 3 steps in its own `try/except Exception` with `logging.exception`; `sync_guests` is skipped, not called with `[]`, when `fetch_guests` raised; the Proxmox step is skipped with one info log when `PROXMOX_URL` is empty, so existing installs keep working after `git pull` and the scan still runs) and `main() -> None` (reads env per Global Constraints, loops with `time.sleep(interval*60)`, or one cycle if `IPAM_SYNC_ONCE=1`).
